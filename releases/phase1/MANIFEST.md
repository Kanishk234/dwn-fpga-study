# Phase 1 release — the design that passed Gate 1b

A frozen copy of the bitstream that passed Gate 1b on hardware, plus everything needed to say
exactly what produced it. Phase 2 will churn the emitters, the RTL and the sweep scripts; this
directory does not change.

**This bitstream is not a fallback for a broken future build — it is the reference.** If a
Phase 2 change makes the board misbehave, reflashing this tells you within a minute whether the
board and the toolchain are fine and the change is at fault.

---

## What passed

```
GATE 1b -- 2026-08-04, Digilent Basys 3 (XC7A35T-1CPG236C)

samples              : 166000        (the entire JSC test set)
hardware == software : 166000/166000
core cycles          : 166815        = 166000 + 162 x (LATENCY+1), so II=1 held on silicon
wall clock           : 11.2 s        at 5 Mbaud
accuracy, float32 model      : 73.8361%
accuracy, Q3.12 (on hardware): 73.8349%
```

Reference for the comparison is the **Q3.12 golden model** — the spec the hardware implements —
not the float32 model. The two differ on 30 of 166,000 samples (0.018%), worth −0.0012 pp; that
is reported as characterization, not folded into the pass/fail.

## The model

The paper's JSC **`sm`** configuration (arXiv:2410.11112, Table 14), reproduced:

| | |
|---|---|
| architecture | single LUT layer, 50 nodes, n=6, learnable mapping |
| encoder | distributive thermometer, z=200 → 3200 bits, of which **202** are wired |
| input format | Q3.12 signed, 16-bit, saturating |
| reduction | 5 × popcount(10) → argmax, lowest index wins ties |
| pipeline | 4 stages, II=1 |
| software accuracy | 73.84% (paper's `sm`: 74.0%) |

## Reproducing this

```
.venv\Scripts\python.exe scripts\run_gate1.py          # regenerate RTL + prove it in sim
.venv\Scripts\python.exe scripts\build_bitstream.py    # build (no flags: 5 Mbaud default)
.venv\Scripts\python.exe scripts\program.py            # flash over JTAG
.venv\Scripts\python.exe scripts\host.py --gate1b      # 166000/166000, ~11 s
```

Bit-for-bit identical output is not expected — Vivado placement varies run to run — but area,
timing and the Gate 1b result should reproduce.

## Reflashing this exact bitstream

```
.venv\Scripts\python.exe scripts\program.py --bit releases\phase1\dwn_basys3_top.bit
```

Programming is volatile: it is lost on power cycle or on pressing PROG. Nothing is written to
flash.

## Using the board

`sw[1:0]` selects the seven-segment display: `00` last class, `01` cycle count, `10` correct
count, `11` cycle count high word. Classes are alphabetical — `0=g, 1=q, 2=t, 3=w, 4=z` — not
the physics ordering.

`led[0]` busy, `led[1]` a run finished, **`led[2]` UART framing error (sticky)**, `led[3:4]`
echo the switches, `led[15:8]` low byte of the correct count.

On a machine that has never run this: set the **FTDI latency timer to 1 ms** or the run is ~21%
slower with no other symptom. `scripts/host.py` detects and warns; `--set-latency 1` fixes it
from an Administrator shell.
